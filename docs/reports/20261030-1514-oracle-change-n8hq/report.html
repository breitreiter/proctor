Tasks

A task is one input and one desired outcome, given to every arm: a prompt against a fixture repository, with the checks that say whether the outcome was reached. Each task is run 5 times per arm, so a score is not one lucky or unlucky attempt.

A check is one yes-or-no test over a finished run. Every task carries the checks the suite declares; a fixture or the task itself can add more. A check's role decides what it does to a run:

headline
Together, the headline checks decide whether a run passed.
validity
Decides whether a run counts at all: a run that fails one is left out of every rate, not counted as a failure.
guardrail
Reported, not part of the pass.

A check that cannot decide a run leaves that run out of its rate on both sides.

Each task's results show one mark per run: ● passed, ○ failed, ? undecided, × not counted. Hover a mark for the reason; click it for the run. A task scores its mean over its counted, decided runs.

Results

Pass rate is the share of counted runs in which every headline check held, averaged task by task so that one task with many runs does not outweigh another. The 95% interval says how far the true rate could plausibly sit from the measured one; with 1 task it is wide.

haiku-harbor against haiku-bare. haiku-harbor passed 20 points more of its runs than haiku-bare. The 95% interval on that difference runs from −56 to +76 points, so with 1 task the difference could be noise: no detectable difference. Task by task, haiku-harbor did better on 1, worse on 0, the same on 0.

With 1 paired task this experiment can reliably detect a difference of about 100 points. To detect 10 points you need about 200 tasks.

Each task is scored as its mean over its counted, decided runs, so n in every interval is the number of tasks. Per-arm rates use the Wilson 95% interval. Differences between arms, and against the baseline, use Newcombe's paired method (Wilson square-and-add, with phi from the per-task scores). The detectable difference assumes 80% power and a per-task paired-difference sd of 0.5. Durations are the run's wall time including hooks; tokens are the run's own count.
