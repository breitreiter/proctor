AI providers: where to get a key

proctor setup links to this page when it asks for a key. Each section says where the provider issues keys and what to know before you use one. Setup keeps the key in a file in your user profile, never in your repository, and checks it by listing the models it can reach, which costs nothing.

  • Gemini (Google AI Studio)
  • Anthropic
  • OpenAI
  • OpenRouter
  • OpenAI-compatible endpoint
  • Azure OpenAI
  • Azure AI Foundry

Gemini (Google AI Studio)

  • Get a key: Google AI Studio → Get API key. The free tier needs no card.
  • The free tier's limits are a few requests a minute and a daily cap, varying by model; nb waits and retries when it is throttled. See Google's rate limits.
  • Free-tier prompts and responses may be used by Google to improve its products; paid-tier ones are not. Keep confidential material off the free tier. See Google's pricing page.
  • Proctor's first real suite, readme-answers, runs on Gemini Flash-Lite's free tier.

Anthropic

  • Get a key: Claude Console → Settings → API keys.
  • This is an API key, billed per request. A Claude subscription (Pro, Max) and its Claude Code login are separate and are not used.
  • Serves nb's built-in harness and Claude Code arms.

OpenAI

  • Get a key: OpenAI Platform → API keys.
  • Billed per request; a ChatGPT subscription is separate and is not used. See how OpenAI treats API data.
  • Serves nb's built-in harness, Codex arms and LLM-as-judge checks.

OpenRouter

  • Get a key: openrouter.ai → Keys. A key can carry a credit limit; set one.
  • One key reaches many vendors' models. Models whose ids end in :free cost nothing, are rate-limited, and their prompts may be logged by the vendor serving them. See OpenRouter's privacy settings.
  • Serves nb's built-in harness, LLM-as-judge and classifier checks. Claude Code and Qwen Code arms through it are untested; Codex through it is set up by hand.

OpenAI-compatible endpoint

  • For llama-server, Ollama, LM Studio, vLLM, Groq, a gateway of your own, or anything else that speaks OpenAI's chat completions.
  • The key, if the server needs one, comes from the server's own documentation; many local servers need none.
  • Setup takes only the name and the key. Ask your coding agent to fill in the rest of the entry in suites/nb.json (the endpoint, the context size, any headers) from the server's documentation; proctor setup --check reports the entry as incomplete until it has an endpoint.

Azure OpenAI

  • Get a key: in the Azure portal, open your Azure OpenAI resource, then Keys and Endpoint. The endpoint is the resource URL shown there.
  • Setup also asks for the deployment name: the name you gave the deployment, not the model's name.
  • Azure does not list deployments with a key, so setup cannot check the key; the first run of a suite on it is the check.

Azure AI Foundry

  • Get a key: in the Azure AI Foundry portal, open your project, then Keys and Endpoint.
  • Setup also asks for the model as deployed in the project.
  • As with Azure OpenAI, setup cannot check the key; the first run of a suite on it is the check.

A provider missing here is set up by hand: see docs/configuration.md.
