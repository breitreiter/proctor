OpenAI-compatible endpoint

  For llama-server, Ollama, LM Studio, vLLM, Groq, or anything else that speaks
  OpenAI's chat completions. These differ in what they need (an endpoint, a
  context size, sometimes headers), so setup takes only the key, which is the
  one part that must not pass through your coding agent. Ask your agent to fill
  in the rest of the entry.

  Name for this provider in your suites: ollama
  API key (enter if the server needs none): ****************************************
  Saved as OLLAMA_API_KEY in /home/ana/.config/proctor/env

  Written:
    suites/nb.json          provider "ollama" (LocalLlm, ApiKey ${OLLAMA_API_KEY});
                            Endpoint and Model left for your agent

  Not checked: setup has no endpoint to ask. `proctor setup --check` reports
  "ollama: incomplete (no Endpoint)" until the entry is filled in, then lists
  its models like any other provider's.

# The name comes first here, since the env variable is named from it
# (<NAME>_API_KEY, uppercased, non-alphanumerics as _).
# With no key, the entry gets no ApiKey and nothing goes to the env file.
# The same pattern serves "A gateway of your own" (any dialect) and Codex's
# by-hand route: setup captures the secret, the agent writes the rest.
